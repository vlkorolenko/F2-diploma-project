# ВСТУП

## Актуальність теми

Зростання обсягу та швидкості випуску програмного забезпечення збільшує кількість вихідного коду, що підлягає перевірці на вразливості безпеки. Статичні аналізатори на основі шаблонів (FindSecBugs, SonarQube) мають високу частку хибнопозитивних спрацювань, що збільшує трудомісткість ручної верифікації та знижує довіру до результатів у CI/CD-конвеєрах.

Великі мовні моделі (LLM) здатні інтерпретувати семантику коду, однак за відсутності структурованого контексту потоків даних і керування демонструють нестабільну точність, недетерміновану поведінку, а їхні виклики характеризуються суттєвою затримкою та вартістю. Граф властивостей коду (Code Property Graph) об'єднує синтаксичну структуру, потік керування та залежності за даними, що дозволяє виділяти шляхи від недовірених джерел до небезпечних операцій і формувати компактний контекст для LLM. Відсутність відтворюваного, інтегрованого в CI/CD методу, що поєднує структурний аналіз графа з семантичною верифікацією LLM, визначає актуальність теми.

## Об'єкт дослідження

Процес виявлення вразливостей безпеки у вихідному коді Java/Spring-застосунків на етапі безперервної інтеграції.

## Предмет дослідження

Методи побудови та taint-аналізу графів властивостей коду, верифікації кандидатів вразливостей великими мовними моделями та архітектурні рішення асинхронної обробки (Spring Boot, RabbitMQ, Neo4j, PostgreSQL) для їх програмної реалізації.

## Мета роботи

Підвищення точності автоматизованого виявлення вразливостей вихідного коду Java/Spring-застосунків (об'єкт) шляхом розроблення та застосування методу, що поєднує аналіз графів властивостей коду і верифікацію великими мовними моделями (предмет), для зменшення частки хибнопозитивних результатів при збереженні повноти виявлення.

## Завдання проєкту

1. Проаналізувати існуючі статичні аналізатори безпеки (FindSecBugs, SonarQube, Semgrep) та підходи до застосування LLM у виявленні вразливостей; обґрунтувати технологічний стек.
2. Спроєктувати архітектуру асинхронної платформи сканування засобами UML, C4 Model та ADR.
3. Розробити алгоритми побудови графа властивостей коду, taint-аналізу для класів CWE та формування програмних зрізів для верифікації LLM.
4. Реалізувати базовий код системи: REST API, воркери обробки, інтеграцію з Joern, Neo4j, PostgreSQL, RabbitMQ та LLM.
5. Налаштувати інфраструктуру розгортання та інтерфейс: Docker Compose, CI/CD (GitHub Actions), метрики спостережуваності (Prometheus, Grafana).
6. Дослідити ефективність методу на OWASP Benchmark та Juliet Test Suite за метриками Precision, Recall, F1 у порівнянні з FindSecBugs і Semgrep; виконати модульне та інтеграційне тестування.
7. Апробувати результати та підготувати наукову публікацію за результатами дослідження.
