# Thesis Proposal

## 1. Робоча назва проєкту

- **UA:** Метод та програмні засоби автоматизованого виявлення вразливостей вихідного коду на основі графів властивостей коду та великих мовних моделей.
- **EN:** Method and Software Tools for Automated Source Code Vulnerability Detection Based on Code Property Graphs and Large Language Models.

**Напрям:** Безпека програмного забезпечення (Application Security & DevSecOps).
**Спеціальність:** F2 Інженерія програмного забезпечення.

## 2. Актуальність та проблематика

Статичні аналізатори безпеки (SpotBugs з FindSecBugs, SonarQube) виявляють вразливості на основі шаблонів і характеризуються високою часткою хибнопозитивних спрацювань, що збільшує трудомісткість ручного аналізу. Великі мовні моделі (LLM) здатні інтерпретувати семантику коду, однак за відсутності структурованого контексту потоку керування та даних демонструють нестабільну точність на проєктах значного обсягу. Також їхні відповіді недетерміновані, а виклики мають суттєву вартість і затримку.

Граф властивостей коду (Code Property Graph, CPG) об'єднує абстрактне синтаксичне дерево, граф потоку керування та граф залежностей за даними в єдине представлення. Він дозволяє виділяти шляхи від джерел недовірених даних до небезпечних операцій (taint-аналіз) і формувати компактний контекст для LLM.

Проблема: відсутність відтворюваного, інтегрованого в CI/CD методу, що поєднує структурний аналіз CPG з семантичною верифікацією LLM для зменшення частки хибнопозитивних результатів при збереженні повноти виявлення.

## 3. Ідея продукту

Асинхронна сервісна платформа виявлення вразливостей у Java/Spring-проєктах. Платформа реалізує двоетапний конвеєр:

1. **Генерація кандидатів:** побудова CPG та виконання taint-запитів для визначених класів вразливостей.
2. **Верифікація кандидатів:** передача програмного зрізу (backward/forward slice) шляху «джерело → стік» до LLM зі структурованою схемою відповіді; формування підсумкового вердикту.

Тип архітектури: модульна подієво-орієнтована система з REST API (Spring Boot), чергою задач (RabbitMQ), воркерами аналізу, графовим та реляційним сховищами, контейнеризована (Docker Compose), з CI/CD та контуром спостережуваності.

## 4. Основний функціонал (Core Features)

1. **Генерація CPG.** Автоматизований розбір Java/Spring-проєкту (Git-репозиторій або архів) та побудова графа властивостей коду з використанням Joern; експорт та збереження графа в Neo4j.
2. **Taint-аналіз за класами CWE.** Бібліотека запитів до CPG для CWE-89 (SQL Injection), CWE-79 (XSS), CWE-22 (Path Traversal), CWE-78 (Command Injection), CWE-502 (Insecure Deserialization) з визначенням Spring-специфічних джерел (`@RequestParam`, `@PathVariable`, `@RequestBody`) та стоків (`JdbcTemplate`, `EntityManager`, `Runtime.exec`).
3. **LLM-верифікація кандидатів.** Формування програмного зрізу, промпт-шаблони, структурований JSON-вивід (вердикт, CWE, впевненість, обґрунтування), валідація схеми, повторні спроби, тайм-аути, кешування за хешем зрізу.
4. **Асинхронне виконання сканувань.** REST API для запуску та моніторингу задач, черга RabbitMQ, воркери, збереження результатів у PostgreSQL; відмовостійкий виклик LLM (Resilience4j: Circuit Breaker, Retry), підтримка локальної моделі як резервної.
5. **Звітність.** Генерація звітів у форматах SARIF та JSON з посиланнями на файли й рядки коду, класифікацією CWE та оцінкою впевненості.
6. **Експериментальна оцінка.** Автоматизований запуск на OWASP Benchmark (Java) та Juliet Test Suite (Java), обчислення Precision, Recall, F1; порівняння з FindSecBugs та Semgrep.
7. **Інтеграція в CI/CD та спостережуваність.** Docker-образ сканера, GitHub Actions workflow з публікацією SARIF у Code Scanning; метрики (Micrometer, Prometheus, Grafana): час сканування, кількість кандидатів, частка підтверджених, витрата токенів.

## 6. Очікуваний результат

Працюючий прототип з відтворюваними експериментами, що демонструє зменшення частки хибнопозитивних результатів порівняно з окремим статичним аналізом при збереженні рівня повноти виявлення.
