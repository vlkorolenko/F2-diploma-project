# Специфікація вимог до програмного забезпечення (SRS)
## Стандарт ISO/IEC/IEEE 29148:2018

### 1. System Context (Контекст системи та межі застосування)
Розроблюване програмне забезпечення являє собою гібридний статичний сканер безпеки коду Java, інтегрований у процеси інженерії безпеки (DevSecOps). Межі системи охоплюють:
* Отримання сирцевого коду від користувача (Software Engineer або AppSec Auditor) через веб-інтерфейс або інтеграцію з GitHub API.
* Внутрішню декомпозицію та синтаксичний аналіз кодових структур з побудовою Code Property Graph (CPG).
* Проведення алгоритмічного Taint-аналізу для вилучення мінімальних кодових зрізів (15–30 рядків).
* Локальну взаємодію з нейромережевим інференс-рушієм Ollama через бібліотеку LangChain4j.
* Компіляторну валідацію синтезованих латок та публікацію Pull Request.

Зовнішнє середовище системи:
* **Клієнтські браузери:** взаємодія через протокол HTTPS з Single Page Application (SPA).
* **Системи контролю версій:** взаємодія з GitHub REST API v3 за протоколом HTTPS з авторизацією через Personal Access Token (PAT).
* **Локальний LLM-сервер:** локальний інференс за протоколом HTTP/REST (порт 11434).

### 2. Functional Requirements (Функціональні вимоги)
* **SRS-FUN-01:** Система **повинна** підтримувати прийом вихідного коду Java-проєктів у вигляді посилання на відкритий чи приватний GitHub-репозиторій або прямого завантаження ZIP-архіву через веб-інтерфейс.
* **SRS-FUN-02:** Модуль препроцесингу **повинен** виконувати повний синтаксичний та семантичний розбір вихідного коду Java (версії від Java 8 до Java 21) на основі бібліотеки Spoon із побудовою абстрактного синтаксичного дерева (AST) та розв'язанням типів.
* **SRS-FUN-03:** Графовий аналізатор **має** генерувати об'єднаний Code Property Graph (CPG), що складається з графа синтаксису (AST), графа потоку керування (CFG) та графа потоку даних (DFG) у межах методів і міжкласових викликів.
* **SRS-FUN-04:** Модуль Taint Analysis **повинен** виконувати спрямований обхід CPG-графа від визначених точок входу даних (`Sources`) до критичних точок виконання (`Sinks`) згідно з сигнатурами стандартів CWE-89, CWE-79, CWE-78, CWE-22.
* **SRS-FUN-05:** Алгоритмічний слайсер **має** вилучати контекстний зріз коду (Program Slice) розміром від 15 до 35 рядків, що включає лише оголошення змінних, передачу аргументів та проміжні трансформації вразливого ланцюжка.
* **SRS-FUN-06:** Інтеграційний модуль LangChain4j **повинен** передавати сформований зріз коду разом із системним промптом валідації до локальної моделі DeepSeek-Coder для остаточного підтвердження факту наявності вразливості.
* **SRS-FUN-07:** Модуль генерації виправлень **має** синтезувати мінімальний безпечний патч коду та верифікувати його компіляцію через системний `javax.tools.JavaCompiler`.
* **SRS-FUN-08:** Система **повинна** надавати інтерактивний веб-інтерфейс із відображенням знайдених вразливостей, інтерактивною візуалізацією графа Taint Path та кнопкою автоматичного створення Pull Request у GitHub.

### 3. Non-Functional Requirements (Нефункціональні вимоги)
* **SRS-NFR-PERF-01:** Час побудови CPG та вилучення зрізу для одиничного Java-файлу розміром до 1000 рядків не повинен перевищувати 35 секунд на 95-му перцентилі (p95 Latency $\le 35$ с).
* **SRS-NFR-PERF-02:** Пропускна здатність бекенд-сервісу API Gateway повинна становити не менше 100 одночасних запитів за секунду (100 RPS) при навантаженні з пулом з'єднань.
* **SRS-NFR-SEC-01:** Система повинна повністю функціонувати в On-Premises контурі, не відправляючи код за межі внутрішньої захищеної підмережі.
* **SRS-NFR-ACC-01:** Рівень False Positive Rate на еталонному наборі тестів OWASP Benchmark v1.2 для категорій SQLi та XSS не повинен перевищувати 15%.
* **SRS-NFR-REL-01:** Модуль черги завдань на базі Redis повинен підтримувати обробку збоїв та чергу «мертвих листів» (Dead Letter Queue — DLQ) для ізоляції файлів, які спричинили перевищення ліміту часу аналізу.
* **SRS-NFR-INFRA-01:** Усі серверні компоненти системи мають бути контейнеризовані з використанням Docker та Docker Compose з лімітами оперативної пам'яті (до 4 GB RAM на контейнер аналізатора).

### 4. Verification Criteria (Критерії верифікації вимог)
| Індекс вимоги | Метод перевірки | Інструментарій верифікації | Критерій успішності |
| :--- | :--- | :--- | :--- |
| **SRS-FUN-01** | Автоматизоване інтеграційне тестування | JUnit 5, Mockito, WireMock | Успішне клонування репозиторію за токеном або розпакування валідного ZIP без втрати файлів |
| **SRS-FUN-02** | Модульне тестування семантичного розбору | JUnit 5, Spoon Test Framework | Коректне визначення типів повернення методів та класів у 100% синтетичних тест-кейсів |
| **SRS-FUN-04** | Еталонне тестування безпеки | OWASP Benchmark v1.2 Test Harness | Виявлення закладених True Positive ланцюжків з точністю $\ge 75\%$ |
| **SRS-FUN-07** | Компіляторна валідація | JavaCompiler API, AssertJ | Згенерований файл виправлення компілюється з нульовим кодом помилки (`DiagnosticCollector.isEmpty()`) |
| **SRS-NFR-PERF-01** | Стрес- та навантажувальне тестування | k6 (сценарій Spike & Load Testing) | Час обробки 95% запитів не перевищує 35 секунд |
| **SRS-NFR-SEC-01** | Мережевий аудит та перевірка витоків | Wireshark, tcpdump, Trivy | Відсутність вихідних з'єднань за межі локального хосту під час інференсу ШІ |

### 5. Glossary (Глосарій технічних термінів)
1. **Code Property Graph (CPG)** — об'єднана структура графових даних, що синтезує абстрактне синтаксичне дерево (AST), граф потоку керування (CFG) та граф залежностей даних (DFG) для поглибленого міжпроцедурного аудиту.
2. **Taint Analysis (Аналіз зараження)** — метод відстеження розповсюдження потенційно небезпечних, несанітизованих даних від джерела введення (`Source`) до критичної точки виконання (`Sink`).
3. **Program Slicing (Кодовий зріз)** — техніка вилучення підмножини вихідного коду програми, яка безпосередньо впливає на значення певної змінної у заданій точці програми.
4. **Automated Program Repair (APR)** — алгоритмічний процес автоматичної генерації виправлень (латок/патчів) для дефектів та вразливостей коду без втручання людини.
5. **False Positive (Хибне спрацьовування)** — ситуація, за якої сканер безпеки помилково маркує безпечний фрагмент коду як критичну вразливість.
6. **LangChain4j** — відкрита Java-бібліотека для декларативної оркестрації та інтеграції великих мовних моделей у JVM-стек.
